# Architecture

Contributor constraints and target responsibilities live in
[CONTRIBUTING.md](../CONTRIBUTING.md); build/validation instructions live in
[DEVELOPMENT.md](DEVELOPMENT.md).

## Pipeline and storage

1. **Acquire:** Android backup via ADB/file, or iPhone backup conversion. Source
   backups are read-only. Decrypt crypt15 locally; keys belong in the Keychain.
2. **Ingest:** append messages to `segments/*.ndjson.gz` in a user-chosen vault.
   `vault.json` describes the vault; `media/` holds locally available media.
   Segments are never edited. Stable message `uid`s match overlapping imports.
3. **Apply rules and index:** rebuild a disposable local SQLite cache from the
   vault. `config/` stores durable contact names, overrides, prune rules and
   merges. Hide messages at index time rather than deleting source data.
   Messages absent from a newer full backup remain in the vault and are flagged
   gone. Index row IDs may change: persistent references use `uid`s.
4. **Browse/query:** `SagaCore` supplies logic to the SwiftUI app, `saga` CLI and
   read-only `saga-mcp` server. The index contains messages, FTS, chats, people,
   media, aliases, aggregate statistics and the disposable merge-identity map
   (original numbers behind a merged person); it is not the archive of record.

Default app storage is `~/Library/Application Support/Saga/`: `vault/`,
`vault_index.db`, `ai_cache.db` (saved AI results and topic lists),
`semantic_cache.db` (meaning-search vectors) and `link_meta.db`. A vault can
live on external/cloud/NAS storage while the rebuildable index stays local.
Vault segments are compressed data. Vault encryption is optional and **off by
default**: when enabled, `segments/*.ndjson.gz` and `config/*.json` are sealed with
AES-256-GCM under a passphrase-derived key, with an independent recovery code kept
on a printable Recovery Kit. `vault.json`, `config/overrides.csv`, `media/`,
`exports/` and the local index/AI/link caches stay plaintext. See
`docs/tasks/02-optional-encryption.md` and the frozen format in
`docs/tasks/02-encryption-contract.md` §8. For whole-storage protection use an
encrypted volume/FileVault; vault encryption is file-level encryption at rest, not
an app lock.

## Media in chats

Attachments are looked up on demand, never copied into the vault and never
scanned at launch. `config/media-sources.json` lists the source folders a vault
uses (written by FoldIn and by **Settings › Archive › Media folders**, which also stores an
optional Google Drive folder in the app's user defaults). For one message the
resolver tries, in order: the recorded relative path under each source, then the
recorded filename plus size, and only then the chosen Drive folder. Lookups read
metadata only; opening an online-only Drive file is what triggers its download.

Image thumbnails and video posters are generated by ImageIO/AVFoundation only for
bubbles that are on screen, at most four at a time, and cached as PNGs in
`~/Library/Application Support/Saga/media-thumbnails/` keyed by vault, message
`uid` and size. A warm cache needs no source lookup, so a second view is instant.
Voice notes resolve their file only when played; documents open in the default
app. Missing, unreadable or unrecorded files render a plain "not available" chip
or a toast, never an error dialog.

## Privacy boundaries

- No analytics. Local archive processing is the default.
- AI model behavior and opt-in link metadata requests are documented in
  [AI.md](AI.md).
- MCP is local over stdio, but its client may send results to a remote model;
  see [MCP.md](MCP.md) before connecting a client.
- The frozen Python `webui` branch is a parity oracle, not an extension target.
  Index schema or segment-format changes need explicit versioning and backward
  readability; use the parity scripts when changing indexing behavior.

Legacy `saga import --also` and `saga compact` support the old direct-merge path.
They are separate from the append-only vault pipeline and remain supported.
